# Memory Checkpoint

Capture where the work stands ACCURATELY, right before a compact or a break, and keep the
memory files honest while you are in them. Two rules govern everything:

- **Accuracy over completeness.** Verify every claim against git and the code; reality wins
  over what memory says. Unsure? Flag it. A wrong memory misleads every future session.
- **Mutable vs locked.** Update the moving parts (status, current focus). Never rewrite the
  master plan, locked decisions or specs, or any file with a "GENERATED by ~/.agents" header;
  touch only their as-built markers, and only if the doc invites it.

## Phase 1: Take stock

`git status`, `git diff --stat`, `git log --oneline -20`. Establish what changed since the
last checkpoint, decisions and why, what is done / in progress / next, and the current phase
(MASTER_PLAN or STATUS, else AGENTS.md "Current focus", else the vault MOC).

## Phase 2: Find the surfaces

- **Guest repo** (`gh repo view --json viewerPermission` is not ADMIN, or the user says so):
  tracked files are not your surfaces. No STATUS.md, no AGENTS.md focus; the doctor pass only
  reports. State goes in `~/Vault/projects/<project>/repo-local/`; the MOC stays an index.
  No mode overrides this.
- **Status doc** (`STATUS.md` or similar): the primary target.
- **AGENTS.md "Current focus"**: only in small repos with no STATUS.md, and never in a rules
  payload. A repo root holding `sync.sh` and `overlays/` is agent-config: its AGENTS.md is
  baked into every session on every repo, so write its STATUS.md instead.
- **Vault**: read the MOC for context; `/save` writes the vault, you don't.
- No status doc and no vault: say so, add a short AGENTS.md focus, suggest `/scaffold` or
  `repo-intake`.

## Phase 3: Write the update

- **Status doc:** follow `/save` step 3 for what it holds, where the edit lands (a merged
  branch or main in a PR repo queues it in `status-queue.md`) and its shape. Match the doc's
  headings, edit in place, no "previously X, now Y". Run `bash ~/.agents/hooks/status-lint.sh
  <repo>` and fix what it prints before writing.
- Unless in auto mode, show the diff and get a nod first.

## Phase 4: Doctor pass

- **Duplication:** `CLAUDE.md` and `AGENTS.md` full copies of each other? Keep `AGENTS.md`
  and collapse `CLAUDE.md` to the one line `@AGENTS.md`.
- **Corruption:** a find-replace copy (Claude<->Codex swaps, files that don't exist)? Verify
  each suspect token against the code and fix it.
- **Staleness:** sections that no longer match the code or plan. Fix mutable ones, flag locked
  ones. `status-lint.sh` finds ids, PR numbers and lifecycle wording; check each against
  `git`/`gh` and rewrite to present-tense state. Re-derive counts (`N functions deployed`)
  from the code. A superseded banner left in place is drift: reconcile it, don't stack another.
  The vault MOC holds pointers only; a `Current state` section there gets replaced by a pointer.

Report what you fixed; if nothing is off, say so.

## Phase 5: Clear to compact

List each path written or fixed with a one-line summary, confirm memory matches reality, and
tell the user it is safe to `/compact`. `/recall` or STATUS.md rehydrates next session.

Modes: auto does the whole pass without stopping; plan reports what it would write; default
shows before writing. No vault or no git: do what you can and say what you skipped.
